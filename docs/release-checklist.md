# Release Checklist

Ozealis is pre-prototype. A release tag should not imply medical approval, safety, or fitness for any use.

## Evidence boundary

The local source-release gate proves repository consistency only. It does not prove electrical, pressure, acoustic, reliability, hygiene, BLE pairing, mobile-device, or human-use safety.

For every hardware, BLE-device, mobile-device, OTA, calibration, or schematic item below, record dated evidence before tagging: command output, platform/build versions, device/PCB revision, firmware hash, app build identifier, photos or screenshots where relevant, exported CSV/JSON artifacts, and notes for any deviation. Do not convert a source-only passing gate into a broader release claim.

- A clean mobile lockfile install `npm ci --ignore-scripts` passes as part of both the local source-release gate and CI, and the CI workflow keeps `GITHUB_TOKEN` at read-only repository contents permission.

- Expo dependency compatibility check passes.
- Mobile production audit summary exactly matches the reviewed advisory baseline, with no unreviewed additions, removals, or severity/directness/path changes and no high or critical advisories.
- BLE protocol verifier passes.

## Required before broader public hardware claims

- Independent electrical validation.
- Independent airflow and pressure instrumentation.
- Overpressure, undervoltage, sensor fault, motor fault, and power-loss behavior captured in logs.
- Incomplete pressure-read behavior verified: one-sided, stale, or non-finite pressure samples emit unknown pressure evidence, do not seed or update the ambient estimate, and cannot produce a finite mask-gauge overpressure decision until both pressure inputs are finite again.
- PAP session synchronization verified: accepted start resets controller/ramp/timing state and enters running green, while stop, low-flow auto-stop, pressure-read loss, shutdown, and fault leave the driver disabled and the system outside running mode.
- Pressure-target ceiling verified across every therapy mode and timed/spontaneous branch: reported setpoint and commanded controller target never exceed 25 cmH2O, including ASV/AutoASV with maximum pressure support.
- Accessory telemetry loss verified: a heartbeat with a short, stale, non-finite, or out-of-range telemetry frame clears readiness and commands zero humidifier/heated-hose heat; prewarm cannot start without a fresh bounded temperature/RH frame.
- Fault-latch preservation verified: once firmware enters `MODE_FAULT`, secondary sensor-health or overpressure checks do not overwrite the active fault code, except for the documented low-VIN recovery path.
- Low-VIN behavior verified on hardware: the filtered VIN initializes from the first ADC reading rather than a synthetic `0 V` boot value; filtered VIN below `9.8 V` for more than `200 ms` records retained `FAULT_LOW_VIN` evidence, recovery above `10.3 V` returns to idle, immediately publishes the `VIN_RECOVER` BLE mode/fault update, and does not erase the retained fault row.
- Motor/blower calibration curves reviewed against independent pressure and current instruments.
- Material and cleaning review for every airflow-path part.
- App-layer BLE authorization or physical commissioning design for settings, control, and OTA.
- Signed-image verification, certificate pinning, or an equivalent documented firmware authenticity design for OTA.
- Clear hardware revision markings in documentation and printed parts.

## Do not tag if

- Any user-facing text claims treatment, diagnosis, screening, cure, prevention, approval, safety, or reliability.
- Firmware cannot be built from the checked-in instructions.
- Mobile app and firmware disagree on BLE UUIDs or settings schema.
- Any known unsafe behavior lacks a documented limitation, mitigation, or test plan.
